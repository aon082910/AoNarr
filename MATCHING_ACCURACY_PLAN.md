# Matching accuracy plan

Scope: bring AoNarr's release-to-item matching (grab, import, scan, IRC, manual) to Sonarr/Radarr behaviour where it matters most, in shippable rounds. The ordering follows the "highest-impact-minimal" plan (both judges asked for the identity gate to ship first, flag-guarded, with log-only dry run); the clean-title index, match-type gating, typed indexer queries and scene-numbering fixes from the "starr-fidelity" plan are grafted in as later rounds. Line anchors were re-checked against the working tree.

## Why media gets mismatched today

Ranked by how many wrong grabs/imports each causes.

1. **Video types have no title gate at all.** `chooseBestResult` (`server/src/services/scheduler.ts:593`) sets `tiered = usesQualityTiers(mediaType)` at `:614`; the `relevant` filter at `:668-691` calls `releaseNameMatch` only inside `if (!tiered)` (`:669-675`). `usesQualityTiers` (`quality.ts:110-115`) is true for movie/series/anime/sports/ppv/video/course/adult, so for them only quality/upgrade/size are checked (`:676-690`). Single-shape callers pass `target: null` (`:1416`, `:1654`, `:2118`). `matchTierFor` (`:326-334`) is documented as a tiebreaker and sorts behind `totalScore` (`:768-771`). `tests/scheduler.test.ts:1896-1902` enshrines "nothing matches identity, still chosen". Example: wanted *Dune (2021)*, query `Dune 2021`, only hit `Dune.Part.Two.2024.1080p.WEB-DL.x265-GRP` → grabbed and imported as Dune (2021). Same for `Dead.Heat.1988` vs *Heat (1995)*.
2. **Episode searches compare numbers only.** `searchEpisode` passes `identity` and `name` as null (`scheduler.ts:1437-1448`); `searchAndGrabTarget` leaves them null for episodes (`:1644-1647`); `retryFailedGrab` likewise (`:2097-2100`). The only gate is `releaseMatchesEpisode`/`releaseMatchesAirDate` (`:648-664`; `releaseParser.ts:460-482`). The manual-search route does the same: `routes/search.ts:190` deliberately sets `identity = null` for episode/season/sub-item searches and `identityExternalIds` is only built for whole-item searches (`:123-149`). Example: *Charmed (1998)* S01E01 grabs `Charmed.2018.S01E01.1080p.AMZN.WEB-DL-NTb` because it has more seeders; *The Daily Show* 2024-08-25 grabs `The.Late.Show.2024.08.25.1080p.WEB-GRP`. The IRC path already does title + ±1 year (`ircAnnounce.ts:76-79`, `:97-99`); search never did.
3. **Identity is only a tiebreaker, never a rejection.** Sort at `scheduler.ts:768-778` is `totalScore → matchTier → …`; `matchTier` can only reorder releases that all survived the (absent) title filter, so a wrong-title release with +50 for x265 is both accepted and preferred. Example: *Up (2009)* chooses `Up.in.the.Air.2009.1080p.WEB.x265-GRP` over `Up.2009.1080p.BluRay.x264-GRP`. The fix is a gate (item 1), not a sort change: once wrong-title releases are rejected, `totalScore` must stay first so custom-format preferences keep deciding among releases that passed identity.
4. **Import selection is a token-overlap heuristic that never re-verifies identity.** `findDownloadedFile` (`importer.ts:477`) widens to all of `config.downloadsDir` when the scoped search finds nothing and there is no episode target (`:498`, `:506`); a reported single file with a non-media extension (`.iso`) falls through `:489-491` straight to that wide search. `scoreByTokenOverlap` (`:422-443`) weights `1080p`/`x264`/group like title words and `numberTokens` (`:257-262`) only sees 1-3 digit numbers, so 2021 vs 2024 never trips `otherNumber`. `pickDownloadedFile` (`:529`) first drops every candidate whose `otherNumber` is set, sorts by score descending then size descending, and keeps those scoring ≥0.4 (`:590-605`) — the winner is the highest token-overlap score, size as tiebreaker, so an unrelated file with enough shared quality tokens wins; the folder-name fallback (`:563-586`) lets an unnumbered extra win. `placeFile` (`:1075`) trusts the queue row; its only parse (`:1137-1166`) adds sibling episodes. `isSharedDownloadFolder` (`:395`) returns "own folder" when `releaseTitleTokens` is empty (`:397-398`), i.e. for titles like *24*, *ER*, *Up*, and `pickDownloadedFile:539-549` only applies the series-title gate when tokens are non-empty. Example: queue row `Dune.Part.Two.2024.1080p.WEB.H264-GRP` with a stale path imports the seeding `Dune.2021.1080p.WEB.H264-GRP.mkv` (5/8 tokens = 0.625, no `otherNumber` because `numberTokens` ignores 4-digit years).
5. **Season packs drop other seasons silently and the data is then deleted.** `planSeasonPackFiles` (`importer.ts:1894`) sets `numbers: []` for another season's file (`:1921`) and does not count it (`:1958`), so `removeQueueItemDownload` runs with `deleteFiles` true (`:2335`). The pack branch of `importQueueItem` (`:2266-2277`) never sets `mayHoldMore`, so the `releaseHoldsMoreMedia` safety check at `:2318` is skipped for packs and only `pack.unmatchedCount/leftInPlace/notUpgradedCount` protect the data. `retryFailedGrab`'s season branch (`scheduler.ts:2110-2116`) pre-filters by season number only (`:2144-2153`) before the shared `chooseBestResult` call (`:2157-2174`). Example: `Show.S01-S02.COMPLETE` with `season_number=1` imports S01 and destroys S02; a failed `ShowX.S02` retry grabs `ShowY.S02.COMPLETE`.
6. **Parser gaps feed 1-5.** `ParsedRelease` (`releaseParser.ts:5-46`) has no title field; the only title isolation is `guessTitleFromText` (`libraryScan.ts:192-223`), which cuts at the FIRST `\b(19|20)\d{2}\b` (so `Blade.Runner.2049.2017` guesses "Blade Runner", `2001.A.Space.Odyssey.1968` and `1917.2019` guess ""), never strips a leading `[Group]`, a trailing ` - 05`, `(1080p)`, `[CRC]` or `2nd Season` (`[SubsPlease] Jujutsu Kaisen - 25 (1080p) [ABCD1234]` guesses `[SubsPlease] Jujutsu Kaisen - 25`). `YEAR` (`:86`, applied at `:400-401`) is the first `\b(19|20)\d{2}\b` anywhere, including an air date's year: `The.Daily.Show.2024.08.25` → year 2024 against an item year of 1996. Season/episode detection (`:340-398`) is an ordered if-chain (`SEASON_EP_RANGE` → fansub `S2 - 05` → `SEASON_EP_X_FORMAT` → `SEASON_ONLY` → `FULL_SEASON_HINT` → batch); it is the attribute extractors (year, airDate, quality, group, languages, edition) that run independently over the whole string, so `French Connection` scores a French language and `Final Destination` an edition. `releaseMatchesEpisode` ORs aired/scene/absolute (`:468-474`) so `Show.S05E01` satisfies both TVDB S05E01 and XEM-mapped S01E05 (the OR itself was a deliberate choice: `releaseParser.ts:454-458`, `scheduler.ts:1428-1431`, CHANGELOG Round 195 at ~5470-5478, because some groups number a XEM-mapped show correctly; the bug is the double match, not the aired fallback). `ABSOLUTE_EPISODE` (`:95`) rejects `- 05v2`; `withoutVersionTag` lives in the importer only (`importer.ts:1062`). `[SubsPlease] Mushoku Tensei 2nd Season - 05` parses as absolute 5 and matches S01E05 because `computeAbsoluteEpisodeNumber` (`importer.ts:49-57`) is a DB row count; the real `episodes.absolute_episode_number` column exists (`db/client.ts:92`, `db/postgresSchema.ts:100`, `db/mappers.ts:83`) but is only written by `routes/metadata.ts:271`. `S01E01.E02`, `S01E01-S01E02`, `1x01-02`, `Season.2.Episode.5`, `MM.DD.YYYY` and seasonless `Complete.Series` are unparsed or mis-typed (`Inception.2010.COMPLETE.BLURAY` becomes a season pack).
7. **Non-tiered name match does not reject a different parent.** `releaseNamesTarget` (`scheduler.ts:446-462`) needs parent tokens only when self-titled; `namesLaterVolume` (`:397`) knows roman numerals only. Example: `ABBA - Greatest Hits (1992)` passes for Queen's *Greatest Hits*; `Super Mario Bros. 3 (USA)` passes for SMB. Note the existing positive cases at `scheduler.test.ts:2008-2172` (`Atomic Habits by James Clear`, `Sapiens - Harari, Yuval Noah [EPUB]`, ROM titles with no parent at all) show that unconditionally requiring the parent would break books/ROMs.
8. **Library scan and bulk add guess.** `pickTitleMatch` (`libraryScan.ts:107-111`) accepts a sole same-title row regardless of year and falls back to `matches[0]`; scan enrichment's `.find` (`:1176-1182`) already requires `sameTitleIgnoringQualifier` AND `fileYear == null || r.year == null || |Δ| ≤ 1`, with `fileYear` passed to `searchMetadata` so same-year hits rank first — its only gap versus `pickVerifiedProviderHit` (`:138-150`, used by `matchAdditionalProviders` at `:2547` and `routes/media.ts:1373`) is the ambiguous case: two or more same-title hits (a remake and the original) with an unknown year on either side, where `.find` takes the first and `pickVerifiedProviderHit` returns undefined; `refreshOneItem` has the same gap when `item.year` is null (`:2064-2085`). `detectSeasonEpisode` (`:306-321`) ignores `parsed.absoluteEpisode` and `parsed.airDate`, so `[SubsPlease] One Piece - 1085` and `The.Daily.Show.2024.05.01` are skipped. `POST /:id/rematch` overwrites `title` (`routes/media.ts:1748-1752`); the scan never revisits tracked files (`knownPaths` at `libraryScan.ts:965`, skipped in `walkForExtensions:392-404`), so existing files stay attached, but a later scan of a NEWLY added episode file whose guessed title is `Greys Anatomy` creates a duplicate row because `titlesMatch("Greys Anatomy", "Grey's Anatomy")` is false under both `normalizeForMatch` and `asciiMatchKey` (`:65-81`). `importLists.ts:470`, `routes/watchlistImport.ts:62` and `routes/discordInteractions.ts:152` take `results[0]` without passing `year` to `searchMetadata`.
9. **No alias storage, canonical-title queries only.** `media_items` has `title`/`sort_title` only (`db/schema.sql:23-48`); `fetchAlternateTitlesFor` (`metadata.ts:3322`) is display-only (`routes/media.ts:1098`). `searchTorznabNewznab` always sends `t=search` (`indexerClient.ts:242-244`), ids only for whole-item video callers (`:246-259`); scene variants run only on zero results (`:552-622`). *Attack on Titan* never matches `Shingeki.no.Kyojin.S04E01`. Movies released under a short title (`Birdman`, `Leon`, `Dead.Reckoning`) never match a metadata title carrying a subtitle.

Every grab-side fix in the history has been a ranking change (CHANGELOG.md:906-911 "purely an additional ranking signal, never a hard filter"; CHANGELOG.md:5938-5945 sorted the manual view).

## How the Starr apps do it (what we port)

- **Parse → resolve → decide**, as separate pure stages. The parser isolates a title; the resolver maps it to exactly one library item by exact equality on a stored `CleanSeriesTitle`/`CleanMovieTitle` column plus alias tables, with an ordered fallback chain (alias → clean title → title+year → indexer id); two hits is a rejection (`MultipleSeriesFoundException`), never `matches[0]`. Crucially, Sonarr's `ParsingService.GetSeries` checks `searchCriteria.Series` first: when the target is already known (a search for a specific item), the release is compared against that item's titles only, and the library-wide ambiguity rejection applies only to unsolicited mapping (RSS, disk).
- **Identity is a hard rejection with a named reason** (`UnknownSeries`, `MatchesAnotherSeries`, `UnknownEpisode`, Radarr year gate), evaluated before quality/format specs. After acceptance, ranking is by quality/custom-format score; neither app ranks by "year present".
- **Year parsing (Radarr):** the first year token that is preceded by at least one title token and not immediately followed by another year token (`(?<year>(19|20)\d{2}(?!p|i|(19|20)\d{2}|\]|\W(19|20)\d{2}))`).
- **Match type recorded on the grab** (`Title`/`Alias`/`Id`); a release matched by indexer id only, not from interactive search, is blocked from automatic import.
- **Scene numbering is converted with precedence**, not OR'd: `GetStandardEpisodes` tries `FindEpisodesBySceneNumbering` first and falls back to `FindEpisode(season, episode)` (aired) only when no episode of the series carries those scene numbers; absolute numbers map through the stored absolute list; numberless specials match an S00 episode title by substring. Hashed-name rejection uses exact-length regexes (`^[0-9a-zA-Z]{32}`, `^[a-z0-9]{24}$`, `^[A-Z]{11}\d{3}$`, `^[a-z]{12}\d{3}$`, `^Backup_\d{5,}S\d{2}-\d{2}$`, …).
- **Import ties back by DownloadId**, never a downloads-wide fuzzy search; each file must map to the grabbed item/episodes (`MatchesGrab`, `MatchesFolder`); unmatched files go to manual import and client data is kept.
- **Typed queries**: `t=tvsearch` with `tvdbid/season/ep`, `t=movie` with `imdbid/tmdbid`, plus per-alias free-text fallback.
- **Users can add an alias from the rejection itself** (Sonarr/Radarr scene-mapping / alternative-title UI), which is the realistic "needs review" recovery.
- **Table-driven parser fixtures** (hundreds of real release names).

Not ported: the ~110-regex ordered parser table, Lidarr fingerprinting, Radarr's exact-year-or-SecondaryYear rule (see Open questions).

## Target design

A new pure module `server/src/services/releaseIdentity.ts` exporting:

- `releaseIdentifiesTarget(releaseTitle, parsed, item, opts) → { ok, matchType: 'id' | 'title' | 'alias' | 'title-main' | 'title-noyear' | 'none', reason }`. Per-item form: compares `parsed.title` against THAT item's title (and from Round 3 its `media_item_titles` rows) only, no library-wide lookup — used by grab, retry, manual search/grab, and import, where the target is already known. Round 1 implements the comparison over `sameTitleIgnoringQualifier` + `normalizeForMatch` (exported from `libraryScan.ts`) plus roman↔arabic numeral equivalence; Round 3 swaps it for exact equality on stored `clean_title` values.
- `resolveReleaseItem(release) → { item, matchType } | { ambiguous: true } | null` (Round 3): the library-wide `clean_title` index lookup with two-hits-is-ambiguous rejection, used only by IRC announces, unsolicited import and scan — never on a grab for a known item (otherwise `The.Office.S03E01` would be rejected for The Office (US) because the UK row also matches).
- `fileContradictsTarget(filePath, folderName, clientTitle, item, target) → reason | null` for the import side.
- `cleanTitle(s)` (Round 3): `normalizeForMatch` output → drop non-leading `a|an|the|and|or|of` → remove `[^\p{L}\p{N}]` with the `u` flag (NOT `\W`, which in JavaScript is `[^A-Za-z0-9_]` and would delete every CJK/Cyrillic/Greek character) → lowercase; no additional `\p{M}` strip (`normalizeForMatch` already strips combining marks on Latin/Greek letters only, deliberately, so `がき` ≠ `かき` and Devanagari/Thai survive); digit-only pass-through; `%` → `percent`; roman numerals I–XX ↔ arabic.
- `identityModeFor(type, opts)`: reads `strictReleaseIdentity.<type>` (per media type, values `off | log | enforce`; a bare `strictReleaseIdentity` value is the default for types without their own key) via `getSetting` from `services/settingsStore.ts`, overridable through `options.identityMode` so `chooseBestResult` tests can exercise `enforce` vs `log` without seeding settings (`getSetting` is synchronous, `settingsStore.ts:71`, and the tests call `chooseBestResult` directly with no DB settings).

Rules:

- **Title:** `parsed.title` (Round 1 parser output, see Round 1) must equal the item title (qualifier-tolerant: `(US)`, `(2018)` peeled and checked as qualifiers; roman ↔ arabic numerals equivalent), or an alias (Round 3), or — with lower rank — the item's main title up to the first `:` / ` - ` (`title-main`, as `namesMainTitle` already does for books), so `Birdman`, `Leon.1994` and `Dead.Reckoning.2023` match metadata titles carrying a subtitle before the alias table exists.
- **Year:** `parsed.titleYear` is a year token that is NOT inside the `AIR_DATE` match and sits before the episode marker. When `parsed.airDate` is set the year check never runs. For `single`-shape movie/ppv targets, when both `titleYear` and `item.year` are known, |Δ| ≤ 1 (declared deviation from Radarr, see Q1). For series/anime targets the year is a qualifier, not a numeric gate (Sonarr): `Charmed.2018.S01E01` matches an item whose titles include `Charmed (2018)`/`Charmed 2018` (the primary title + year is always an implicit alias); `Charmed.1998.S01E01` matches neither `Charmed` nor `Charmed 2018` for the 2018 item and is rejected; a yearless `Charmed.S01E01` matches the known target on grab.
- **Id:** indexer `imdbid`/`tmdbid`/`tvdbid` equal to the item's bypasses both and yields `matchType: 'id'`; item `year == null` accepts a yeared release as `title-noyear`.
- **Per-type strictness:** movie/series/anime use the exact/alias gate above. sports/ppv/course/adult/video (also `usesQualityTiers`, but their item titles are folder-derived or rarely verbatim in releases: `UFC.300.Pereira.vs.Hill.PPV` vs `UFC 300`, course titles, site rips) use a `looseTitlesMatch`-style whole-word containment of the item title in `parsed.title`, and stay in `log` until a corpus from real announces exists. Anime stays in `log` (or `enforce` scoped to items that already have alias rows) until Round 3 aliases and Round 4 fansub conventions land, because every fansub-named release depends on title isolation + synonyms.

Per surface:

- **Grab** (`chooseBestResult` via `searchSingle`, `searchEpisode`, `searchSubItem` video path, `searchAndGrabTarget`, `retryFailedGrab`): identity gate inside the tiered branch before quality filters; episodic targets keep `releaseMatchesEpisode` AND identity; sort unchanged (`totalScore` first, `matchTier` stays the tiebreaker); `ChosenResult` (`scheduler.ts:783` currently `{ result, quality }`) gains `matchType`/`identityReason`, `grabBestRelease`'s retry loop carries it, and `grab()` (`scheduler.ts:852`) records `match_type` and `grab_source` on the queue row.
- **Import**: no widening beyond the reported path; `fileContradictsTarget` in `placeFile` and per file in `planSeasonPackFiles`; a mismatch throws `ImportIdentityMismatchError`, a plain `ImportSkippedError` subclass that propagates out of `importQueueItem` and is handled by the generic skipped path in `importCompletedDownload` (`scheduler.ts:2270-2288`: row stays `completed` with `import_skipped_reason`, manual-interaction notification, data kept) and `markQueueImportFailed` (`:2326-2329`); rows with `match_type = 'id'` whose `grab_source` is not `interactive` (NULL counts as manual/legacy and is NOT blocked) are left for manual import.
- **Library scan / auto-match**: `pickTitleMatch` rejects a sole match on year contradiction only for `single`-shape files (or files with no season/episode/airDate), using `titleYear`; ambiguous year-less files skip with a review log; enrichment and Refresh use `pickVerifiedProviderHit`; absolute and air-date files importable.
- **IRC**: `resolveReleaseItem` (gaining aliases), candidates scoped by the new `irc_feeds.media_types`, loop continues when `tryGrabMatch` declines.
- **Manual**: interactive search computes `matchesTarget` from the per-item predicate and returns `identityReason`; `POST /grab` and `/import/manual*` return 409 with the reason unless `force: true`; the rejection UI offers "add this title as an alias and grab".

"Needs review" instead of auto: a release whose identity is `none` is rejected and logged, never grabbed; an import whose file contradicts the target stays as a queue row visible in Activity; a scan file with two same-title rows and no year is skipped and logged; bulk adds with ambiguous hits go to `import_review_items`; an anime release with a `Part N`/`Final Season` qualifier and no alias row is rejected, not guessed.

### Round 1 — Parser title + identity gate for tiered types, log-only then enforce (M)
**Status: shipped, in `log` mode.** `ParsedRelease.title`/`titleYear` (`releaseParser.ts`), `services/releaseIdentity.ts` (`releaseIdentifiesTarget`, `identityModeFor`), the gate inside `chooseBestResult`'s tiered branch, `name` + `identity` passed by every tiered caller (single, episode, season-pack retry), `queue.match_type`/`queue.grab_source` (both schemas), the manual search's `identityOk`/`identityMatch`/`identityReason` annotations and `grab_source = 'interactive'` on a manual grab, and the per-search indexer-id tally in the log. Title normalization moved to `services/titleMatch.ts` (re-exported from `libraryScan.ts`). Every type runs in `log`: the container log shows `identity gate (log-only) would reject "…": <reason>` for each release `enforce` would drop. **To enforce:** set the `strictReleaseIdentity` setting to `enforce` (all types) or `strictReleaseIdentity.movie` / `.series` per type; `off` disables the gate. Known gap left for Round 3 aliases: a dropped possessive brand (`Agents.of.S.H.I.E.L.D` for "Marvel's Agents of S.H.I.E.L.D."). Not done in this round: `rejected` (hashed names, Round 4), alias rows (Round 3).
**Goal:** stop wrong-title video grabs on every indexer-backed path.
**Files/functions:**
- `releaseParser.ts`: `ParsedRelease` gains `title`, `titleYear`, `rejected`. Title isolation lives here, not in `guessTitleFromText`: strip a leading `LEADING_BRACKET_GROUP` and bracketed/parenthesised tags, then cut at the earliest index of the season/episode/absolute/airDate match already found (`rangeMatch.index`, `dashMatch.index`, the `ABSOLUTE_EPISODE` index, the `AIR_DATE` range), the chosen title-year, or the first quality/source/codec/edition token. `YEAR` selection at `:400-401` adopts the Radarr rule: the first `(19|20)\d{2}` token that has ≥1 preceding title token and is not immediately followed by another year token, excluding tokens inside the `AIR_DATE` match range and the trailing `-GROUP` (so `Blade.Runner.2049.2017` → 2017, `2001.A.Space.Odyssey.1968` → 1968, `Nineteen.Eighty-Four.1984.2024.Remake` → 2024, `1917.2019` → 2019, `1917.1080p` → no year, `x264-2024` → no year). `parsed.year` keeps the old first-token value for one release as `firstYear` for diffing; `titleYear` is the new value. A release the delay profile holds back wakes its target (misses back to 0), and so does a held IRC announce. The count starts over when something is grabbed for the target and when the admin edits the item, an episode, a season's monitoring, an alias, a rematch, a quality, delay or release profile (also deleting one), a custom format or its score, an indexer (add, edit, or a Jackett/Prowlarr sync that adds one or changes its types) or a download client, when a file goes missing, and when the RSS sync sees a release for it. The `searchBackoff` setting `0` turns the backoff off. **Auto-upgrade limits** (D15): the upgrade job skips targets the backoff holds, searches the longest-unsearched first, no more than `autoSearchMaxPerCycle`, stamps what it searches and groups a season's candidates into one pack search. **Interactive season search** (S22): the route asks under every season number the scene gives the aired season (lowest first), lists a release found by two of the queries once, and takes the packs of each as its own. **RSS sync** (S1 long term, `rssSync.ts`, a scheduled job every `AONARR_RSS_SYNC_INTERVAL_MINUTES`, default 15, `0` turns it off): each enabled Torznab/Newznab indexer's newest releases are read with no query (the type's categories, the tv or movie feed where the capabilities have one, up to three pages back to the newest release the last run saw, one page on the first run; table `rss_sync_state` keeps where each feed was read to) and a plain RSS indexer's feed is read whole. Each release is matched to the wanted item it names (`resolveReleaseItemInLibrary`, the way an IRC announce is), judged with exactly the rules of a search (`chooseBestResult`: identity, rejections, quality, formats, delay profile, pack guards) and grabbed (`grab_source` `rss`; upgrades too when `autoUpgradeEnabled` is on). While the sync runs, an automatic search leaves the plain `rss` indexers out; an admin's search, a bulk search and a retry still look through them. A feed's marker is kept only once the releases above it were judged: a run cut short (aborted, or a download client down) reads them again, a feed that was empty on its first read stores none, and a marker is never dated after now. **Independent review and the Postgres run:** the Postgres run found a defect that SQLite hid (the Postgres driver appends `RETURNING id` to every insert, and the two new tables have no `id` column, so every backoff write and marker save would have failed; both are now in `TABLES_WITHOUT_ID` in `asyncDb.ts`) and tests that assumed concurrent episode searches run in order. The reviewer (12 findings, all traced in code) found: searches no indexer answered counted as misses and stamped; delay-held releases counted as misses; markers saved before the releases were judged; scene and aired season numbers mixed up (queue coverage, retry, RSS group key, season backoff key); many edits that change what a search finds not resetting the backoff; whole-table backoff resets; a pack sent twice by the search and the RSS job in the same minute, and a multi-episode release sent once per episode in one RSS run; admin and retry searches no longer reaching plain RSS feeds; season searches for sports, course and adult shows, and a manual search advancing the automatic backoff; smaller marker and ordering slips. All were fixed, with tests. **Known gaps:** the RSS sync reads the quality-tier types only (series, anime, films and the like), not books, music or comics; a release that only the delay profile holds back is found again by the target's own search after the wake, since a feed does not list it twice (there is no pending-release store, unlike Sonarr); no UI for `seasonPackGuards`, `seasonPackShare`, `searchBackoff` or the env var; a multi-episode release is still queued against its first episode only (a sibling's own search may fetch it again, as before); while the sync runs the back catalogue of a plain `rss` indexer is not searched; `loadWanted` reads every wanted episode each run (every monitored episode with upgrades on); a TVDB-numbered pack for a show with scene numbering is not matched (scene numbers first, as `releaseMatchesEpisode` does).

## Not changing

- Quality tiers, custom-format scoring, delay profiles, size bounds, seeder/age sort and the sort order itself (`scheduler.ts:697-778`, `quality.ts`): the identity gate slots before them; `totalScore` stays first and `matchTier` stays the tiebreaker.
- DownloadId-keyed queue association in `applyClientStatuses` (`scheduler.ts:2441`; the equality is at `:2455`): already Starr-shaped; only the by-name rekey gets the predicate.
- `normalizeForMatch`'s Unicode handling (`libraryScan.ts:44-55`, Latin/Greek-only combining-mark strip) and `titlesMatch` exact-only semantics (`:65`): they become the first stage of `cleanTitle`; other normalizers adopt it, not the reverse.
- `isSharedDownloadFolder`'s empty-token return (`importer.ts:397-398`): the *24*/*ER* fix lives in `pickDownloadedFile`, so `collectSeasonPackFiles` keeps working for short titles.
- No wholesale Sonarr ordered-regex parser port: the existing if-chain plus a `title` field and corpus-driven additions is cheaper.
- Album/book placement (`placeAlbumFiles`), Lidarr fingerprinting: out of scope; the music fix is the narrow different-parent rejection in `releaseNamesTarget` (Round 3), not a parent requirement.
- Scan still creates items from folders; it just stops enriching from ambiguous hits and stops attaching single-shape files to year-contradicting rows.
- `pathTail` media-server heuristics and blocklist per-item scope: follow-ups.
- Manual grab/import stay overridable (soft 409 + `force`), never hard-blocked.

## Decisions (answered 2026-10-24)

1. **Movie year tolerance: ±1**, the IRC path's current convention (`ircAnnounce.ts:79`). No `secondary_year` column.
2. **sports/ppv/course/adult/video: whole-word containment of the item title, in `log` mode** until a corpus of real announces shows the rule is safe. movie/series keep the exact/alias gate; anime deferred to Round 3 as planned.
3. **Every result rejected: log only**, Sonarr-style. No `import_review_items` row.
4. **Typed search support: probe `t=caps` on every indexer**, cached per process start, automatic free-text fallback. No per-indexer opt-in.
5. **Blocked imports keep seeding until acted on.** The row stays in Activity flagged for manual import with the data kept; the stalled-cleanup timer does not apply to them.
6. **Alias backfill: a background job after the Round 3 migration**, one provider call per item through the existing Background Jobs widget, rate-limited. Refresh keeps aliases current afterwards.
7. **Anime numbering: AniList absolute first, TVDB/XEM fallback** when the release carries SxxEyy. `episodes.absolute_episode_number` is the stored source.
8. **Indexer ids: unknown; Round 1 logs per indexer how many results carried `imdbid`/`tmdbid`/`tvdbid`.** The Round 2 id-only import block is kept or dropped from that data.
9. **`.iso`/`.img` single-file downloads: left for manual import** with reason `unsupported-extension`. Movie extensions unchanged.
10. **Scene numbering: scene-first precedence with aired fallback**, replacing the Round 195 OR, behind a `sceneNumberingMode=or` rollback setting.
